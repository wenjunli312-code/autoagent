MasterAgent（极薄语音路由器）· Parking Agent（全权执行）· Tool 体系

🎙️

MasterAgent

语音路由器
纯自然语言路由 · 不懂泊车领域知识
只维护「有哪些子 Agent + 各自负责什么」的清单
收到用户说"停到阴凉车位" → 原封不动转发给 Parking Agent
📍 8775 芯片

Cockpit Agent

📍 8775 芯片 · L1 本地记忆

与 Parking Agent 无直接通信
set_temp设定空调温度

🅿️

Parking Agent

📍 Thor-U 芯片 · L1 本地记忆 · 断连自治
全权执行泊车任务
接收用户原始指令，理解 + 规划 + 执行全包
detect_slots检测可用车位（前视+4环视）
check_conditions判断"阴凉/充电桩"等约束
plan_trajectory规划泊车轨迹 → waypoints
check_clearance检查路径是否畅通
inform_user向座舱/用户反馈进度
retry_or_abort失败时重试或放弃
🧭 问题 1：MasterAgent 对泊车来说只是一个"语音路由器"？
✅ 是的。MasterAgent 极薄，只做两件事：
① 听用户说什么 → 判断属于哪个子 Agent（泊车 → Parking Agent）
② 把用户原话转过去，等待结果回来告诉用户
MasterAgent 不需要理解"阴凉"是什么意思、不需要知道泊车流程。
泊车领域的全部智能都下沉到 Parking Agent 里。
🔗 问题 2：Agent 和 Tool 的关系？
Agent（LLM + 推理循环）决定「做什么」「用什么做」「做完了下一步做什么」
Tool（函数/API）是被调用的能力单元

关系链：
用户指令 → Agent 推理 → Tool 调用 → 观察结果 → 再推理 → 再调用…… → 完成

关键洞察：对 MasterAgent 来说，子 Agent 就是它的一个 Tool。
MasterAgent 调 park_the_car("停在阴凉车位")，背后是一个完整的 Agent 循环在运行。
🔄 问题 3：座舱（Cockpit）和 Thor 之间没有直接关系？
✅ 第一阶段：两者无直接通信。部署在不同芯片上，各自独立运行。

唯一的联系链路是：
用户 → MasterAgent → Cockpit / Parking（各自转发）

后续如果需要跨域推理（如"停好车后关空调"）才需要引入：
Parking Agent → State Summary → MasterAgent → Cockpit Agent
但第一阶段不涉及，先做单域。
